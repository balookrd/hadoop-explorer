# Руководство пользователя SQL Web Explorer

<p>Веб-интерфейс для выполнения аналитических запросов к Trino и Apache Hive с ИИ-ассистентом</p>

</div>

---

Руководство для аналитиков данных и дата-инженеров, которые работают в SQL Web Explorer. Это веб-консоль для SQL-движков Trino (PrestoSQL) и Apache Hive (HiveServer2 / Cloudera / Hortonworks): навигация по метаданным (Hive Metastore / Iceberg / Delta Lake), редактор Monaco с несколькими вкладками, потоковая отдача результатов и ИИ-ассистент.

## 1. Функции SQL Web Explorer

С консольными клиентами (`beeline`, `trino-cli`) аналитик сам следит за `LIMIT`, долго ждет загрузки схем и теряет историю сессий при смене устройства. SQL Web Explorer закрывает эти задачи в браузере:

```mermaid
graph TD
    User(["Аналитик / Дата-инженер"]) -->|"HTTPS / SSO"| UI["SQL Web Explorer UI\nSvelte 5 + Monaco Editor"]
    UI -->|"REST + SSE Streams"| Gateway["SQL Explorer API\nJava 21 + Spring Boot 3"]
    Gateway -->|"TrinoSqlEngine / HiveSqlEngine"| Mock["MockSqlEngine\nдемо-каталоги и результаты"]
    Gateway -->|"встроенные правила"| AI["AiService\nбез обращения к LLM"]
    Gateway -->|"рабочее пространство и история"| DB[("H2")]
```

В текущей версии `TrinoSqlEngine` и `HiveSqlEngine` делегируют все вызовы в `MockSqlEngine`: запросы в Trino и HiveServer2 не отправляются, каталоги, схемы и результаты берутся из встроенного демо-набора.

- Trino и Apache Hive в одном окне: переключение между Trino и HiveServer2 без смены инструмента.
- Редактор Monaco: подсветка синтаксиса, автодополнение ключевых слов и имен таблиц и колонок, форматирование SQL, несколько вкладок запросов.
- Потоковая отдача результатов через Server-Sent Events (SSE): строки выводятся по мере их получения с кластера, интерфейс при этом не блокируется.
- ИИ-ассистент: генерация SQL по текстовому описанию, AST-проверка запроса на запрещенные DML/DDL, статический анализ производительности (декартовы произведения, отсутствие фильтра по партициям, лишний shuffle) и пошаговое объяснение логики.
- Сохранение рабочего пространства: открытые вкладки, текст запросов, расположение панелей и история хранятся в базе данных сервера, поэтому работу можно продолжить на другом компьютере.
- Кэш результатов и экспорт: ранее выполненные выборки открываются без повторного запуска на кластере; фильтрация на клиенте; экспорт в CSV (с защитой от Formula Injection) и JSON.
- Безопасность: вход через Kerberos SPNEGO SSO или LDAP, разграничение доступа к кластерам по ролям (RBAC). Метод имперсонации (`impersonation.method`: `header`, `doAs`, `session`) задается в конфигурации кластера и показывается в списке кластеров; к Trino и Hive он не применяется, потому что движки не обращаются к кластерам.

## 2. Архитектура и потоки данных

```mermaid
sequenceDiagram
    autonumber
    actor U as "Аналитик"
    participant UI as "Monaco Studio UI"
    participant BE as "SQL Explorer API (Spring Boot 3)"
    participant DB as "Session & History DB"
    participant ENG as "Trino / Hive Cluster"

    U->>UI: Ввод запроса и нажатие Cmd+Enter
    UI->>BE: POST /api/v1/queries/execute {cluster_id, query}
    BE->>BE: Проверка прав ACL и AST-валидация DDL/DML
    BE->>DB: Сохранение записи в query_history (QUEUED)
    BE-->>UI: "200 OK {query_id, status: QUEUED}"

    UI->>BE: GET /api/v1/queries/{query_id}/stream (SSE)
    BE->>ENG: Асинхронный запуск под учетной записью пользователя
    ENG-->>BE: Чанки метаданных и строк
    BE-->>UI: "data: type=columns, columns=[...]"
    BE-->>UI: "data: type=rows, rows=[...]"
    ENG-->>BE: Исполнение завершено
    BE->>DB: Сохранение результатов на диск (GZIP) и обновление query_history (FINISHED)
    BE-->>UI: "data: type=finished, total_rows=N"
    UI-->>U: Отображение таблицы результатов и времени исполнения
```

## 3. Аутентификация и ролевая модель безопасности

SQL Web Explorer проверяет пользователей через Active Directory / OpenLDAP и поддерживает Kerberos SPNEGO SSO.

<div align="center">
  <img src="images/sql/01_login_screen.png" alt="Экран входа SQL Web Explorer" width="850" />
  <p><em>Рисунок 1: Экран аутентификации LDAP & Kerberos SPNEGO SSO</em></p>
</div>

### Ролевые группы и доступ к кластерам

Доступ к кластерам задает администратор в секции `sql.clusters` файла `application.yml` (см. [руководство администратора](sql-admin-guide.md), раздел 2, шаг 4): у каждого кластера есть списки `allowed-users` и `allowed-groups`. Кластер доступен пользователю, если его имя или одна из его групп есть в этих списках, если оба списка пусты или если пользователь входит в группу администраторов (`hadoop.security.auth.admin-groups`). Ограничения по типу операций (только SELECT, запрет DDL/DML) Explorer не проверяет: в таблице ниже это пример политик на стороне кластера.

| Группа пользователей | Trino Analytics (Prod) | Hive HDP Cluster | Apache HiveServer2 | DDL/DML (DROP, ALTER) |
| :--- | :---: | :---: | :---: | :---: |
| Data Platform Admins (`data-platform-admins`) | полный доступ | полный доступ | полный доступ | да |
| Data Engineers (`data-engineers`) | полный доступ | полный доступ | полный доступ | только в staging/dev |
| BI Analysts (`bi-analysts`, `reporting`) | только SELECT | нет (закрыто ACL) | только SELECT | нет (read-only) |

Заголовок `X-Trino-User` и параметр `hive.server2.proxy.user` сервис не передает: `TrinoSqlEngine` и `HiveSqlEngine` делегируют запросы в `MockSqlEngine` и к кластерам не подключаются, поэтому политики Ranger на кластере к ним не применяются.

### Элементы интерфейса

1. Верхняя панель (Header):
   - переключатель активного кластера Trino/Hive;
   - профиль пользователя и назначенные роли;
   - кнопка **Logout**.
2. Левая боковая панель (Sidebar):
   - вкладка **«Схема»** — дерево каталогов, схем, таблиц и колонок;
   - вкладка **«Очередь»** — активные запросы на кластере;
   - вкладка **«История»** — журнал выполненных запросов.
3. Разделитель панелей (Resizable Splitter):
   - перетаскиванием мыши меняет ширину боковой панели и высоту области результатов;
   - двойной клик сбрасывает размеры к значениям по умолчанию.
4. Панель вкладок (Tabs Bar):
   - кнопка **«+»** создает вкладку;
   - вкладки можно переименовывать, переключать и закрывать.
5. Панель инструментов (Query Toolbar):
   - **«Выполнить»** (Cmd+Enter / Ctrl+Enter);
   - **«Остановить»** — отмена запроса;
   - **«Формат»** — форматирование SQL;
   - кнопки ИИ-ассистента: **«ИИ Генератор»**, **«Анализ»**, **«Объяснить»**, **«Оптимизировать»**.

## 6. Редактор SQL и выполнение запросов

### 6.1. Редактор Monaco и автодополнение
- Подсветка синтаксиса SQL (ANSI SQL, Trino SQL, HiveQL).
- Автодополнение ключевых слов, агрегатных и оконных функций, колонок.
- Выполнение выделенного фрагмента: если в редакторе выделен блок текста, `Cmd+Enter` выполняет только его.

### 6.2. Асинхронное выполнение и потоковая отдача данных (SSE)
После запуска запроса интерфейс подключается к SSE-потоку. Панель инструментов показывает статус («Постановка в очередь...», «Исполнение на кластере...»), время выполнения и число полученных строк.

### 6.3. Таблица результатов, фильтрация и экспорт (CSV / JSON)
- Фильтрация на клиенте: поле поиска отбирает строки в таблице без повторного запроса к серверу.
- Пагинация: переключение между страницами результатов.
- Экспорт в CSV: спецсимволы экранируются, значения защищены от CSV Formula Injection (DDE).

## 10. ИИ-ассистент (AI SQL Studio)

ИИ-ассистент работает на встроенных правилах, без обращения к LLM (см. раздел 12).

### 10.1. Генерация SQL по описанию

Опишите задачу на русском или английском языке — ассистент вернет SQL-запрос.

<div align="center">
  <img src="images/sql/08_ai_generator.png" alt="ИИ-генератор SQL-запросов" width="850" />
  <p><em>Рисунок 8: Генерация аналитического SQL с учетом отсечения партиций HDFS и защиты OOM</em></p>
</div>

Генератор применяет приемы оптимизации:
- Partition Pruning: условия на поля партиционирования в `WHERE` пишутся без оборачивания полей в функции, чтобы движок отсекал каталоги HDFS по датам.
- Top-N Pushdown: снижает нагрузку на единственный Reducer.
- Сокращение сетевого shuffle между узлами YARN.

## 12. Частые вопросы

### Почему запрос в Hive начинает выполняться с задержкой?

Trino выполняет запросы в памяти на worker-узлах. Apache Hive компилирует запрос в DAG Apache Tez или задачу MapReduce и запрашивает контейнеры у YARN ResourceManager — это время уходит до старта выполнения. Прогресс виден на панели инструментов.

---

### Сохраняются ли результаты запросов после закрытия браузера?

Да. Сервер сохраняет результаты завершенных запросов на диск в формате GZIP. Откройте вкладку **«История»**, найдите запрос и нажмите **«Загрузить результат»** — результат откроется без повторного выполнения на кластере.

---

### Как подключить локальную LLM к ИИ-ассистенту?

В текущей версии подключить LLM нельзя. Ассистент (`AiService` в `backend/sql`) проверяет, форматирует и переписывает SQL встроенными правилами и не отправляет запросы к модели. Параметры `sql.ai.url`, `sql.ai.model` и `sql.ai.provider` (по умолчанию `mock-builtin`) в `application.yml` только отображаются в статусе ассистента.
